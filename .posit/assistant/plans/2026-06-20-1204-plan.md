# Plan: Standardize Table and Matrix Formatting Across Chapters

This plan outlines the approach to ensure all textbook chapters (`lesson-*.qmd`) that feature tables or matrices have visual formatting completely consistent with the standards established in `lesson-matrix-operations.qmd`.

---

## 1. Context and Standards

In the final section of `lesson-matrix-operations.qmd`, we established a highly refined table format for representing matrices and tabular data. Depending on whether a table is static or dynamically generated, we have two distinct consistent formats to apply across all other chapters:

### A. Static Markdown Table Standards
For tables written directly in Markdown (e.g., in `lesson-matrix-intro.qmd`, `lesson-graphs-directed.qmd`):
1.  **Centered Columns:** All columns (including row headers) aligned to the center using `:---:`.
2.  **Row Headers:** Left-most header cell is empty (or blank spacer), and row headers themselves are bolded (e.g., `**A**`, `**Case 1**`).
3.  **TeX Math Cells:** Cell values representing numeric values or indicators are wrapped in math mode dollars (e.g., `$0$`, `$1$`, or `--` / `*--*` for blocked diagonals).
4.  **Quarto Captions:** A blank line separates the table from the Quarto label caption, which follows the format `: Description {#tbl-label}`.

### B. Dynamic R `kbl()` Table Standards
For tables generated dynamically in R code chunks (e.g., in `lesson-matrix-multiplication.qmd`, `lesson-positions-struct-equiv.qmd`):
1.  **Compact Sizing:** All `kable_styling()` calls must use `full_width = FALSE` to prevent small matrices from stretching awkwardly across the screen.
2.  **Clean Theme:** Consistent bootstrap styling options `bootstrap_options = c("striped", "hover", "condensed", "responsive")` for adjacency/role matrices, and `bootstrap_options = c("hover", "condensed", "responsive")` for row/column vectors.
3.  **First Column Bold:** Row headers are bolded using `column_spec(1, bold = TRUE)`.

## 2. Execution Plan

We will systematically review and update all chapter files featuring tables:

### Step 1: Standardize Static Markdown Tables
*   **Target Files:** `lesson-graphs-directed.qmd`, `lesson-graphs-ties.qmd`, `lesson-matrix-intro.qmd`, `lesson-sna-ego-networks.qmd`, `lesson-theory-diffusion.qmd`, `lesson-theory-ties-bound.qmd`, `lesson-theory-ego-homo.qmd`, `lesson-theory-tie-strength.qmd`.
*   **Actions:**
    *   Align column formatting delimiters to `:---:` where centering is desired.
    *   Format row header text to be bold (e.g. `**Row Name**`).
    *   Standardize blocked diagonals to `--` or `*--*` consistently.
    *   Ensure a single blank line before the Quarto `: Table Caption {#tbl-label}`.

### Step 2: Standardize Dynamic `kbl()` Tables
*   **Target Files:** `lesson-matrix-multiplication.qmd`, `lesson-positions-struct-equiv.qmd`, `lesson-sna-blockmodeling.qmd`, `lesson-graphs-metrics.qmd`, `lesson-graphs-directed-metrics.qmd`, and other files identified in our audit.
*   **Actions:**
    *   Locate all `kable_styling(...)` calls.
    *   Replace `full_width = TRUE` with `full_width = FALSE` so that matrices render as tightly wrapped blocks.
    *   Add `full_width = FALSE` where no `full_width` parameter is specified.
    *   Ensure parameter formatting (`format = "html", align = "c"`) is clean and standard.

---

## 3. Verification Plan

After applying these modifications, we will:
1.  Re-run `quarto::quarto_render()` on several updated chapters to ensure that all tables compile perfectly with no warnings.
2.  Inspect the rendered HTML pages to confirm that all tables and matrices appear beautifully centered, compact, and completely consistent.
